## Install and import

Disable the previous add-on, restart Blender to unload its modules, and install
the v0.4 ZIP with Preferences > Add-ons > Install from Disk. This installs code;
it is separate from WorldBridge's **Import DarkRide Backup** world picker.

The world picker offers **All Supported Files**, JSON, Compressed JSON and World
Archives. It shows `.json`, `.json.gz`, `.gz`, `.zip` and `.content.zip`. Gzip is
detected by signature. ZIP members ending in JSON or gzip are checked for an
object with an `Entities` array of objects. Nested directory layouts are supported.
Multiple valid worlds produce a named choice with entity counts; nothing is
silently selected. Interactive ZIP inspection runs on a worker; Esc cancels it.

Leave **Download HTTP(S) models** off (the new default) to create the complete
world layout without model downloads. Domain backups use parent-local transforms;
leave the world-space script-export option off. Enabling initial downloads retains
the default four-model limit. A new full import deliberately creates a new collection.

ZIPs are read in place, never extracted. Decompression uses bounded memory, so
there are no decompressed temporary files to clean up. Limits: 512 MiB decoded
backup / aggregate ZIP+decoded candidate budget, 10,000 archive entries, 128
candidate JSON files, and ZIP expansion ratio <=1,000. Duplicate names, absolute
paths and traversal paths are rejected. Asset payloads are not decompressed.
Malformed/unsupported files fail before entity creation. JSON whitespace is not
preserved; every parsed source field is preserved in the sidecar.

## Select an area

1. Use Blender's top/front/side/perspective views and native box selection to select
   placeholders, anchors or imported meshes. For selection through objects, use
   Blender's X-ray selection as appropriate. **Load Selected Area** resolves each
   selection to its original entity anchor, deduplicating multiple selected meshes.
2. Alternatively, click **Create / Select Area Region**. The wire cube starts at
   the 3D cursor, with 20-unit sides. Move with G, scale with S, rotate with R; X/Y/Z
   constrain the operation. Change Z scale to exclude elevated structures. Use
   **Load Selected Area (Region)**.
3. The default rule includes entity origins on or inside the region. **Intersect
   Entity Bounds** instead tests visual bounds in region coordinates. This is a
   conservative bounding-box overlap: it can include empty corners of rotated or
   disconnected models, and is not exact triangle intersection. Entities without
   mesh bounds fall back to their origin. Zero-volume regions are rejected.
4. Review selected entity count, eligible model instances, unique model URLs,
   cache hits, required downloads and skipped instances. Click OK to start.
   **Model Limit** is applied deterministically; 0 means all eligible selected
   instances, not the entire world. Use a small limit for a first test.

Selection never reparents or relocates anchors. Parents outside the region remain
as existing anchors. Descendants are not implicitly included merely because a
parent is selected. Invisible models, non-model entities, unsupported URLs and
already-loaded instances are skipped. Original IDs, transforms and asset references
stay in their sidecars. Bounds use current Blender positions; asset metadata comes
from the original sidecar. Repeating selected loading fills missing models without
duplicating completed ones.

## Progress, retry and storage

Downloads are sequential worker jobs with bounded HTTP timeouts and 128 MiB model
limits. Blender scene construction is batched; at most one native model import
runs per tick. **Cancel Import** preserves completed objects and placeholders.
A native FBX/glTF import already executing cannot be interrupted mid-call.
Repeat the selection operation to retry failures. **Refresh Cache for Retry**
re-downloads unloaded selected models; the old cached file is replaced only after
a successful download. It does not reload completed model instances.

Model caches remain beside each source sidecar, including when selection spans
several imported worlds. Reports default to the project imports directory when
that project exists, otherwise `~/WorldBridge/imports`. The full import picker can
override its output directory. Logs are in the system temp directory under
`WorldBridge/worldbridge-import.log`; reports and sidecars are durable files in the
chosen import directory. Keep sidecars and cache paths with saved Blender scenes.

## Cameras and lights

The genuine world contains **225 Light entities and no Camera entities**. A
read-only audit of cached FBX files for the first 100 eligible model instances
found **92 embedded cameras and 150 embedded lights**. With Blender's default
camera and light, the totals are exactly the observed **93 cameras / 376 lights**.
This explains the counts without treating embedded objects as world entities.

Embedded model cameras are removed by default after the native importer returns;
Blender's FBX import operator has no camera-exclusion parameter. Child object
world transforms are retained. Camera name, transform, type, focal length and
clipping are recorded on the entity anchor; the unchanged cached FBX preserves
the complete source camera data. Enable **Keep Embedded Model Cameras** before
loading if needed. **Show WorldBridge Cameras** affects retained cameras only;
the user's unrelated scene cameras are left alone.

**Show Light Gizmos / Extras** toggles Blender's shared Extras overlay in the
current workspace. Blender 4.2/4.5 do not expose a separate light-only overlay
toggle: this also hides camera/empty/region gizmos. It does not hide light objects
or change their illumination. Turn Extras back on to adjust the region.

**Enable Light Contribution** sets WorldBridge light energy to zero or restores
its captured original energy. **Enable Lights Only Inside Region** additionally
uses light-entity origins. After moving/scaling the region, click **Apply Light
Region Now**. Embedded lights follow their owning entity's origin. The source
light data remains unchanged in sidecars/cached assets. Native world-light intensity
conversion remains approximate; advanced DarkRide lighting conversion is deferred.

## Texture recovery and findings

New model imports look for missing image filenames in the configured read-only
rescue directory's `texture-rescue` subtree. If all matching filenames have one
SHA-256 content hash, the image is copied into `cache/textures` and relinked.
Different matching contents are reported as ambiguous. Source files are never
modified; no missing texture is fabricated. Existing models can use **Recover
Selected Missing Textures**. Diagnostics are on anchors, in import reports, or
in the Blender Text Editor for explicit recovery operations.

Tests on copies of the actual rescued FBX files recovered `hedgedif.jpg`,
`hedgedif.png` and `judgrass.png`. Three grass candidates have identical contents.
The barrel references `barrel [AlbedoM].png`, `barrel [Normal].png` and
`barrel [Roughness].png`; these were not found in the rescue filename inventory.
Its `metalnessblack.png` was recovered. Missing external images explain the
remaining pink materials; merely caching the FBX does not supply these files.

General web texture discovery, external glTF buffer/image fetching, ATP/FST and
extensionless asset support remain deferred. Self-contained GLB/glTF and embedded
FBX images continue to work. Recovery is limited to explicit local filename
matches. No world-wide asset crawl is triggered by area loading.

## Validation and interactive acceptance

Standalone regressions cover gzip/ZIP compatibility, traversal/duplicate rejection,
size limits, ambiguity, source preservation, cache previews, cancellation and
failure handling. Genuine fixtures are read-only and hash checked. Headless suites
in Blender 4.2.0 and 4.5.0 compare all 2,121 world transforms/parent links, exercise
the actual ZIP import operator, test origin/bounds selection, selected loading,
duplicate prevention, camera suppression and light controls. Actual rescued FBX
textures are also tested from private copies. See ignored `build/v04-*` reports.

Interactive verification still needed: visible browser filters and multi-world
choice dialog; top/front/side box selection and X-ray behaviour; region manipulation
and selection preview; cancel/retry responsiveness during long native imports;
material appearance and rendered lighting. Headless tests do not prove these.
No v0.4 interactive acceptance pass or full-world model stress import is claimed.

World export/round-trip editing, exact geometric intersection, advanced lighting
conversion, shared-mesh instancing and general remote texture dependency resolution
remain outside this local build. The add-on ZIP contains code only, no private
worlds, textures, models, credentials or generated audit reports.
